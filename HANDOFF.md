# Передача проекта: с чего начать

Это проект «AI Gave Me a Job». Всё ТЗ лежит в `CLAUDE.md`. Сейчас готов только внешний вид, данные пока фейковые. Задача: подключить настоящие сервисы и запустить проект. Работать нужно через Claude Code. Каждый шаг — отдельный промпт, после каждого шага проверка.

## Что поставить (один раз)
1. Платная подписка Claude (Pro или Max).
2. Claude Code: десктопное приложение Claude, вкладка Code (или CLI).
3. Node.js LTS и Git.
4. Phantom на телефоне и на компьютере, включить devnet (Settings → Developer → Testnet mode).

## Шаг 0. Аккаунты (без кода, ~1 час)
Создать и записать ключи в менеджер паролей:

| Сервис | Зачем | Что взять |
|---|---|---|
| GitHub | хранит код | приватный репозиторий `ai-job` |
| Vercel (вход через GitHub) | хостинг сайта | — |
| Supabase | база данных | `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` |
| Helius | чтение блокчейна | API key (devnet и mainnet) |
| Cloudflare Turnstile | капча | site key и secret key |
| Кошелёк TREASURY (Phantom) | сюда приходят фисы | только **адрес**, ключ никогда не даём серверу |
| Кошелёк PAYOUT (новый, отдельный) | с него идут зарплаты | адрес и приватный ключ (только в env) |

Взять devnet SOL на оба кошелька: faucet.solana.com.

**Правило:** ключи и секреты пишем только в `.env.local` и в Environment Variables на Vercel. Никогда не отправляем в чат, в код, в GitHub.

## Шаги 1–12 (каждый — промпт в Claude Code)
Начало каждой сессии: «Прочитай CLAUDE.md и HANDOFF.md. Делаем шаг N. Сначала покажи план, потом делай. В конце скажи, как мне проверить.»

| # | Что делаем | Готово, когда |
|---|---|---|
| 1 | Залить код на GitHub, задеплоить на Vercel, завести `.env.local` | сайт открывается по ссылке vercel.app |
| 2 | Таблицы Supabase из CLAUDE.md, RLS, доступ только с сервера | таблицы видны в Supabase, с клиента прочитать их нельзя |
| 3 | Создать тестовую монету (SPL, 6 decimals) на devnet, раздать себе 100k+ и 1M+ | монета видна в Phantom (devnet) |
| 4 | Helius: баланс адреса, минимальный баланс за 24 ч, стаж, сброс при продаже, баланс казны | вставляешь адрес, видишь реальный баланс и бонус |
| 5 | Сессия по адресу (httpOnly cookie), лимиты по устройству и IP (не больше 2 адресов на устройство в сутки), гость с ожиданием 15 минут, Lock через подпись, Turnstile перед сменой | гость, адрес и Lock работают, второй человек не может занять залоченный адрес |
| 6 | Серверный движок работ: сервер выдаёт seed, игра строится по нему, сервер сам проверяет ответ и минимальное время, одна активная смена, кулдаун 30 минут на сервере | подделать результат через DevTools нельзя, все 15 работ засчитываются |
| 7 | Поинты и почасовой расчёт: pg_cron в Supabase (или cron-job.org) раз в час вызывает защищённый эндпоинт; пул 20%/24, потолок 5%, 12 оплачиваемых смен в день, овертайм 25% | раз в час в `payroll_hours` появляется строка, балансы считаются правильно |
| 8 | Автовыплаты с PAYOUT на devnet: пачки по ~20 переводов, минимум 0.01 SOL, без повторов (идемпотентность), аварийная пауза | SOL реально приходит в Phantom, повторный запуск не платит дважды |
| 9 | Живые данные вместо `lib/mock.ts`: Payroll, бегущая строка, лидерборд, резюме, история, карточки для X `/p/[id]` | на сайте не осталось ни одной фейковой цифры |
| 10 | Админка `/admin` (вход по паролю или Lock-адресу команды): пауза выплат, баланс PAYOUT, ручная выплата, бан адреса, лог | всё управляется кнопками |
| 11 | Полный тест на devnet: 3 человека, телефоны, сутки работы; попытки абуза: чужой адрес, пустой кошелёк, продажа, спам смен, подделка ответа | ошибок нет, абуз не проходит |
| 12 | Запуск (см. ниже) | первая настоящая выплата дошла |

## Шаг 12. Запуск
1. Убрать превью-кнопки: Skip break, Simulate the hourly payout, Try a specific job, `sampleFor()`.
2. Создать монету на pump.fun. Получатель creator fees — адрес **TREASURY**. Монета не Cashback Coin. Получателя фисов можно сменить только один раз.
3. Mint монеты прописать в env, переключить env на mainnet (Helius mainnet, `SOLANA_CLUSTER=mainnet-beta`), сделать redeploy.
4. Склеймить фисы на pump.fun, отправить суточный пул на PAYOUT.
5. Сделать одну смену самим, дождаться почасовой выплаты, проверить в Phantom.
6. Анонс в X.

## Каждый день после запуска
- Клеймить фисы на TREASURY и пополнять PAYOUT примерно на сутки вперёд. Больше на PAYOUT не держать.
- Смотреть админку: выплаты идут, ошибок нет.
- Если что-то не так, нажать паузу выплат, потом разбираться.

## Безопасность (нарушать нельзя)
- Ключ TREASURY никогда не попадает на сервер.
- Ключ PAYOUT хранится только в переменных Vercel. Его нет на клиенте, в логах и в git.
- Адрес работника берётся только из сессии, не из запроса.
- Всё сначала проверяем на devnet, потом на mainnet.
- На сайте не обещаем «гарантированный» доход.

## Если застрял
- Скопировать ошибку целиком в Claude Code и написать: «вот ошибка, почини и объясни, что было».
- Если ошибок много: «откати последние изменения, сделаем этот шаг мельче».
- После каждого рабочего шага делать commit и push, чтобы было куда откатиться.
